# Reviewed ADCB maintenance

`setup-workflows/25-reviewed-adcb-maintenance.json` is an inactive subworkflow,
excluded from the regular workflow import and every acquisition schedule. Import
it explicitly only after the typed Actual maintenance implementation, exact image,
backup, and approved plan have passed review. It has no manual trigger or webhook:
invoke it from the finite-window scheduled acceptance parent. The parent must
be generated by
`integrations/n8n/setup-workflows/runner/generate-production-acceptance-workflow.py`,
use an Execute Workflow node targeting W25, wait for completion, and process at
most one chunk per scheduled execution. It must stop maintenance calls after a
verified `complete: true` receipt or when the reviewed UTC window expires;
unpublish the acceptance parent after its final receipt. A manual/CLI execution
of this subworkflow is not a substitute for that integrated entrypoint. The Actual node's
existing mutation-disabled credential and manual-execution guards remain in force.

Bind the immutable OneDrive plan item, its exact file SHA-256, the typed plan's
canonical `plan_sha256`, the verified backup receipt SHA-256, Actual sync/account,
expected final count/balance, and a dedicated receipt folder. The file hash and
canonical plan hash are distinct. Bind `approvedPlanSha256` on the Actual node to
the same reviewed canonical hash as the fixed binding node; this parameter must
be a literal, never an n8n expression. Caller input cannot replace these bindings.
Never put a live plan, account identity, or credential value in source control.

Bind W18 and its PostgreSQL credential to the existing production lease service.
Every chunk acquires `actual:<actual_file_id>`, the same global resource as W20,
with a 600-second lease. Fence assertions run before and after the typed mutation.
The operation checks lease expiry before each mutation and applies at most 100
actions per call. Keep other writers/schedulers stopped during reviewed account
reconstruction as required by the deployment plan.

A chunk returns `PARTIAL` until the typed operation verifies the final approved
state. Every partial and final result is reduced to an explicit redacted field
list, written to OneDrive under a unique execution/hash filename, downloaded,
and hashed again. The workflow releases the exact lease only after receipt
readback; a PostgreSQL readback proves release. `complete` is true only for a
verified final result matching the bound count and balance. Partial is progress,
not completion. Neither state changes a source cursor or Cashback period.

For another chunk or a crash retry, invoke the same immutable plan under a newly
acquired lease. The typed operation reconciles every existing action against
Actual; it does not trust a supplied continuation cursor. A changed or conflicting
row fails closed. A failure after Actual persistence but before receipt archival
must be retried through this same reconciliation path. W16 records the redacted
failure, and an unreleased lease expires without resetting any audit state.

Before production adoption, prove bounded multi-chunk completion, exact final
readback, zero-mutation replay, interrupted partial recovery, lease contention,
stale fence rejection, changed plan/account/backup rejection, and archive failure
recovery on a disposable Actual ledger. No production execution is authorized by
merely generating or importing this export.

Run native receipt-node checks against the reviewed installed n8n modules:

```sh
N8N_NODE_MODULES=/path/to/reviewed/n8n/node_modules python -m unittest discover -s tests -p test_adcb_maintenance_workflow.py -v
```

The harness exercises actual extraction, JSON serialization and OneDrive upload
implementations with synthetic bytes and a mocked network boundary. It does not
claim a live OneDrive write or Actual replay; those remain disposable/live gates.
